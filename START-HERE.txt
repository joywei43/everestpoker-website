EVEREST WAITING LIST — 雲端同步與員工登入版

目前尚未部署雲端。單獨上傳 HTML 不會啟用同步。
帳號：admin01。請將你指定的密碼設成 Cloudflare ADMIN_PASSWORD secret。
密碼不包含在公開 HTML 或 GitHub 程式內；登入由 Worker 驗證。

A. 雲端後端（先做一次）
1. 建立／登入 Cloudflare 帳號。電腦安裝 Node.js LTS。
2. 終端機切換到本包 backend 資料夾，依序執行：
   npm install
   npx wrangler login
   npx wrangler d1 create everest-waiting
3. 複製上一步產生的 database_id，貼入 backend/wrangler.toml 的
   REPLACE_WITH_D1_DATABASE_ID（保留引號）。
4. 建立資料表：
   npx wrangler d1 execute everest-waiting --remote --file=schema.sql
5. 部署 Worker：
   npx wrangler deploy
6. 設定密碼：
   npx wrangler secret put ADMIN_PASSWORD
   在隱藏輸入提示中輸入本次指定的密碼，再按 Enter。
   請勿將此密碼寫入 wrangler.toml 或 GitHub。
7. 記下部署後的 https://everest-waiting-api.你的子網域.workers.dev 網址。

B. 前台連接（再上傳 GitHub）
1. 打開 site/waiting-list/config.js，將 REPLACE 網址整段換成上面 Worker HTTPS 網址。
   例如 window.EVEREST_API_URL = 'https://everest-waiting-api.example.workers.dev';
2. 進入原本 Everest 網站 GitHub repository，打開 Pages 的發布目錄。
3. Add file → Upload files，拖入 site 裡的 waiting-list 整個資料夾。
   是 waiting-list，不是 site，也不是 ZIP，不要改動首頁 index.html 或 CNAME。
4. Commit changes，等網站重新部署。
5. 玩家頁 https://everestpokerroom.com/waiting-list/
   員工頁 https://everestpokerroom.com/waiting-list/admin/

C. 驗證
1. 電腦在 admin 頁以 admin01 與設定的密碼登入，新增測試候位。
2. 手機開玩家網址，約 5 秒內應看到新增候位。
3. 更新一個座位紅／白燈，確認手機跟著變化。
4. 登出後應回登入畫面；無 token 的 API 更新應回 401。
5. 若顯示未連線，請先檢查 config.js 網址、Worker 部署、D1 綁定與 schema。

行為與限制
- 所有裝置共用 D1 資料，每 5 秒更新；不是毫秒即時推播。
- 後台 session 存於 sessionStorage，8 小時後過期，登出會撤銷 token。
- 無登入只能讀取公開桌況、候位暱稱與叫號，不能寫入。
- 兩名員工同時更新會以版本檢查拒絕較舊資料，載入新狀態後需重做該次操作。
- 斷線時暫停編輯，避免將本機狀態當成已儲存。
- 同遊戲＋同級別的多桌共用候位。不同遊戲／級別各自編號、叫號。
- Others 為單一分類；不同其他遊戲若要分別排隊，後續需增加自訂遊戲名稱。
- 原本本機版 localStorage 不會自動匯入；第一次雲端使用從空桌、空名單開始。
- 前台公開資料只應輸入暱稱，不要填電話或私人聯絡資訊。
- 現有 HTML 與後端語法及 API 邏輯已檢查；尚未在你的 Cloudflare 帳號部署或實機驗收。
- Cloudflare 與 GitHub 為不同服務；無需移轉網域 DNS 也能使用 workers.dev API。
- 使用量受 Cloudflare 帳號方案配額限制。

後端自測：在 backend 資料夾執行 node test.mjs。
